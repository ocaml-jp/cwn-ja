* betacalendars 1.0.0 — 決定論的な日付・カレンダーユーティリティ
:PROPERTIES:
:CUSTOM_ID: 1
:END:
Archive: https://discuss.ocaml.org/t/ann-betacalendars-1-0-0-deterministic-date-and-calendar-utilities/18593/1

** Beta Calendars が発表しました


*betacalendars* の最初の安定版リリースを発表できて嬉しいです。これはタイムゾーンに依存しない市民日付演算と決定論的なカレンダー生成のための OCaml ライブラリです。

このライブラリは、グレゴリオ暦の日付演算、設定可能な月・年グリッド、有界な繰り返しルール、日付範囲およびカレンダー境界ユーティリティを提供します。ローカルタイムゾーンに依存せず、日付のみを扱う予測可能な処理向けに設計されています。

opam でインストールできます：

#+begin_example
opam update
opam install betacalendars
#+end_example

- ソース: https://github.com/mateopedersen/betacalendars-ocaml
- リリース: https://github.com/mateopedersen/betacalendars-ocaml/releases/tag/v1.0.0
- API ドキュメント: https://mateopedersen.github.io/betacalendars-ocaml/
- opam パッケージメタデータ: https://github.com/ocaml/opam-repository/blob/master/packages/betacalendars/betacalendars.1.0.0/opam

このパッケージは OCaml 4.14 および 5.5 でテストスイートと生成ドキュメントを含めてテスト済みです。フィードバックやご質問をお待ちしています。
      



* Sedlex 3.8.1
:PROPERTIES:
:CUSTOM_ID: 2
:END:
Archive: https://discuss.ocaml.org/t/ann-sedlex-3-8-1/18595/1

** Hhugo が発表しました


Sedlex 3.8.1 がリリースされました！ 🎉

Sedlex は OCaml 向けの Unicode 対応レキサージェネレータで、もともと LexiFi の Alain Frisch によって書かれ、現在は [[https://github.com/ocaml-community][ocaml-community]] の傘下でメンテナンスされています。

目玉機能は *名前付きキャプチャグループ* です。サブパターンを OCaml の ~as~ 構文で束縛し、アクション内で読み返すことができます：

#+begin_src ocaml
match%sedlex buf with
| (Plus ('0'..'9') as num), '.', (Plus ('0'..'9') as frac) ->
    let n = Sedlexing.Utf8.of_submatch num in
    let f = Sedlexing.Utf8.of_submatch frac in
    Printf.printf "integer=%s fractional=%s\n" n f
| _ -> ()
#+end_src

キャプチャはタグ付き DFA で実装されているため、生成されるレキサーはバックトラックなしの単一パスのままです。~as~ を使用しないレキサーは以前と同じコードを生成します。サブマッチは最長マッチ内で左端優先の貪欲マッチです。~as~ は ~Star~、~Plus~、~Opt~、~Rep~、~Compl~、~Sub~、~Intersect~ の下では使用できません。

このリリースには他にも以下の変更が含まれています：

- Unicode 18.0.0 への対応
- Latin1、UTF-8、UTF-16 における ~lexeme~、~sub_lexeme~、~of_submatch~ の高速化

リリースノートは
https://github.com/ocaml-community/sedlex/releases/tag/v3.8 （未リリース）および
https://github.com/ocaml-community/sedlex/releases/tag/v3.8.1 でご覧いただけます。

まもなく opam でも利用可能になる予定です。

* shakuhachi v0.4.0
:PROPERTIES:
:CUSTOM_ID: 4
:END:
Archive: https://discuss.ocaml.org/t/ann-shakuhachi-v0-4-0/18599/1

** EruEri が発表しました


皆さん、

shakuhachi v0.4.0 のリリースを発表できて嬉しいです。

Shakuhachi は引き続き音楽コレクションマネージャーです。

このリリースでは、主な未実装の 2 つの機能が実装されました：
- コマンドラインから float/date プロパティをクエリできるようになりました
  #+begin_example
  # 例: 過去 24 時間以内に再生された *Googoosh* の全楽曲を一覧表示
  $ skhc list %played_at:1dago..now %artist:Googoosh
  # または S 式構文で
  $ skhc list -Q "(and %played_at:1dago..now %artist:Googoosh)"
  #+end_example
- アーティストのクエリ時に複雑な統計がようやく計算されるようになりました
  #+begin_example
  # 例: アルバムが 2 枚以上あるすべてのアーティストを一覧表示
  $ skhc list -Iartist %album_count:2..
  #+end_example

このリリースではより合理的なタグ付け/プロパティ書き込みもサポートされています。
- 楽曲を追加する際、プロパティ /ALBUMARTISTS/（それぞれ /ARTISTS/）が最初に参照され、/*ALBUMARTIST/（それぞれ /*ARTIST/）にフォールバックします。
- タグ付け時に、アーティスト名とアルバムアーティスト名の間の結合フレーズを設定する 2 つの新しいオプション /-j/ と /-J/ が追加されました
#+begin_example
$ skhc tag -a "Sona Jobarteh" -j '&' -a "Youssou N'Dour" Kambengwo.flac
# ARTIST を単一の値として、ARTISTS を 2 つの値を含む値として設定します
# ARTIST = Sona Jobarteh & Youssou N'Dour
# ARTISTS = Sona Jobarteh | Youssou N'Dour
#+end_example

https://codeberg.org/EruEri/shakuhachi

お時間をいただきありがとうございます。

*** Docfd とは

テキストファイル、PDF、DOCX などに対するインタラクティブな grep のようなものですが、正規表現や行ベースではなく単語/トークンベースなので、行をまたいだ検索が簡単にできます。

Docfd は一般的なテキストエディタや PDF ビューアとの統合によって優れた UX を提供することを目指しており、キー一つで検索結果に直接ジャンプできます。

**FFI を多用した OCaml の WebAssembly へのコンパイル：MOPSA に関するエクスペリエンスレポート -- Réda Boudrouss**

大規模な OCaml アプリケーションは OCaml FFI を通じてネイティブの C/C++ ライブラリに依存することが多く、ブラウザ上での実行が困難です。既存のブラウザバックエンドは OCaml を JavaScript や WebAssembly にコンパイルしますが、ネイティブ依存関係のスタックは残したままです。

本発表では、別のアプローチを探ります：Emscripten を使用して OCaml ランタイムと完全なネイティブ依存関係スタックを WebAssembly にコンパイルし、その上でオリジナルの OCaml バイトコードを実行する方法です。FFI 呼び出しは既存の FFI コードや CamlIDL が生成したバインディングを変更せずに、静的なプリミティブテーブルを通じて解決されます。

このアプローチを LLVM/Clang、GMP、MPFR、Apron、CamlIDL を組み合わせた静的アナライザー MOPSA で実証し、完全なアプリケーションがウェブブラウザ上で直接動作できることを示します。

**OCaml における集合論的型ライブラリの設計 -- Mickaël Laurent**

このトークでは、集合論的型のライブラリを設計するために OCaml を使用した経験を共有します。集合論的型はいくつかの再帰的なコンポーネントとレイヤーで構成されているため、定義が難しいです。さらに、再帰型に対する特定の操作の停止性は、さまざまなレベルで動作する hash-consing システムに依存しています。一部の再帰モジュールの型検査を通過させることの難しさや、hash-consing システムの実装に algebraic effects をどのように活用したかなど、OCaml を使用することの課題と利点について議論します。

* faker 0.1.1: faker-js とシード互換のフェイク（しかしリアルな）データ
:PROPERTIES:
:CUSTOM_ID: 7
:END:
Archive: https://discuss.ocaml.org/t/ann-faker-0-1-1-fake-but-realistic-data-seed-compatible-with-faker-js/18611/1

** Bartek Teodorczyk が発表しました


[[https://ocaml.org/p/faker][faker]] を発表できて嬉しいです。これは名前、住所、メールアドレス、電話番号、会社名、日付、金融データ、lorem ipsum などのフェイクだがリアルなデータを 77 のロケールで生成するライブラリです。

#+begin_example
opam install faker
#+end_example

私が調べた限り、OCaml には faker スタイルのライブラリがありませんでした。QCheck のようなプロパティテストジェネレータはランダムな値を生成しますが、デモ、開発用データベースのシード、スナップショットテストのためのもっともらしくローカライズされたフィクスチャは生成しません。

faker は [[https://github.com/faker-js/faker][@faker-js/faker]] 10.6.0 のポートで、**シード単位のパリティ**を持ちます：同じシードに対して、すべてのメソッドが faker-js と全く同じ値を返します。同じ MersenneTwister19937 ジェネレータと同じアルゴリズムを使用しているため、OCaml サービスと JS/TS サービスでフィクスチャを共有できます。

#+begin_src ocaml
let () =
  let f = Faker.create ~seed:42 () in
  print_endline (Faker.Person.full_name f);
  print_endline (Faker.Internet.email f);
  print_endline (Faker.Location.city f);
  print_endline
    (Faker.Helpers.fake "{{person.firstName}} works as a {{person.jobTitle}}" f);
  let de = Faker.Locales.De.faker () in
  Faker.seed de 42;
  print_endline (Faker.Person.full_name de);
  let ja = Faker.Locales.Ja.faker () in
  Faker.seed ja 42;
  print_endline (Faker.Person.full_name ja)
#+end_src

#+begin_example
Nikita Crist
Moises.Sipes-Effertz18@gmail.com
Lolaville
Jeannette works as a Forward Implementation Analyst
Melinda Dragu
吉川 結衣
#+end_example

同等の faker-js コードは同じ 6 行を出力します。

**含まれる機能**

- faker-js のすべての 26 モジュール（~Faker.Person~、~Faker.Internet~、~Faker.Location~、~Faker.Date~、~Faker.Finance~、~Faker.Commerce~ など）とすべての 77 ロケール。
- API は faker-js を踏襲しているため、[[https://fakerjs.dev/api/][faker-js API リファレンス]]がすべてのメソッドを説明しています。faker インスタンスは常に最後の引数で、オプションはオプショナルなラベル付き引数です：`faker.number.int({ min: 1, max: 10 })` は `Faker.Number.int ~min:1 ~max:10 f` になります。
- stdlib と ~unix~ 以外の依存関係なし。ロケールはオンデマンドでリンクされるため、英語のみのプログラムは他の 76 ロケールを持ち込みません。

**パリティの検証方法**

~dune test~ は OCaml の出力を faker-js 自体を実行して生成したフィクスチャと比較します：すべてのケースで 3 つのシード、さらにすべてのロケールのすべてのメソッドのスイープ（約 72,000 チェック）。これらすべてをパスさせるには、ここで興味深いいくつかの問題を解決する必要がありました：

- **FMA 縮約。** arm64 では、OCaml コンパイラが ~a *. b +. c~ を単一の融合積和演算に縮約し、V8 と異なる丸めが行われます。このポートでは必要な箇所で明示的な乗算を使用しています。
- **評価順序。** OCaml は関数の引数とレコードフィールドを右から左へ評価するため、すべてのランダムドローは faker-js の順序で ~let~ で束縛されています。
- **UTF-16 セマンティクス。** JS の文字列長、大文字小文字マッピング、NFKD 正規化が UTF-8 文字列上でエミュレートされ、テーブルは Node から生成されています。
- **浮動小数点演算。** `location.nearbyGPSCoordinate` は V8 の fdlibm ~sin~/~cos~ のポートを使用しています。既知のプラットフォーム依存性の一つは指数分布器における ~Math.pow~ です：Node はシステムの libm を呼び出すため、faker-js 自体が FreeBSD で最後のビットを異なる丸めで処理します。opam-repo-ci がこれを発見し、0.1.1 がその修正です。

ポーティングノートは [[https://github.com/barteo/faker-ocaml/blob/main/docs/PORTING.md][docs/PORTING.md]] にあり、残りの違いは [[https://github.com/barteo/faker-ocaml#readme][README]] の "Known differences" に記載されています。

**リンク**

- パッケージと API ドキュメント: https://ocaml.org/p/faker
- ソース: https://github.com/barteo/faker-ocaml
- Issues: https://github.com/barteo/faker-ocaml/issues

すべてのデータとアルゴリズムは faker-js に由来するため、faker-js チームとコントリビューターに深く感謝します。フィードバックやバグ報告、特に faker-js と出力が異なるケースはぜひお知らせください。
