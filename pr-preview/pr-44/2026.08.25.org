*** Cohttp.Path.resolve_local_file におけるパストラバーサル

問題は、この関数が URI パスをパーセントデコードする前に正規化している点にあります：

#+begin_src ocaml
let resolve_local_file ~docroot ~uri =

   let path = Uri.(pct_decode (path (resolve "http" (of_string "/") 
uri))) in

   ...
#+end_src

~%2f~ は Uri.resolve の後にデコードされるため、エンコードされたセパレータがドットセグメントの正規化を生き残ってしまいます。例えば、以下のようなリクエストパス：

#+begin_example
/static/..%2f..%2f..%2fetc/passwd
#+end_example

は単一のエンコードされたセグメントとして正規化された後、以下のようにデコードされます：

#+begin_example
/static/../../../etc/passwd
#+end_example

[[https://github.com/mjambon/yamlx][YAMLx]] 0.5.0（[[https://github.com/mjambon/yamlx/releases][リリースノート]]）をリリースしました。[[https://discuss.ocaml.org/t/ann-yamlx-pure-ocaml-yaml-1-2-1-1-library/17970][4月の最初のアナウンス]]以降のいくつかの修正と改善が含まれています。YAMLx は、複雑な YAML 1.1 および 1.2 仕様を実装した pure-OCaml ライブラリです。この人気のあるフォーマットでデータを操作するための、完全でありながら便利なユーザーインターフェースの提供を目指しています。

退屈なアナウンスはさておき、YAMLx プロジェクトの異色な側面に（再び？）注目していただく良い機会です。このプロジェクトは3つの主要な軸において異端的かつ実験的です：

*** AI の活用
- 実装のほとんどは AI によって生成されています（約1万行）。
- インターフェースはほぼ人間が設計しています（約800行）。

*** 著作権モデル
- プロジェクトには従来の意味での貢献者が一人だけです。
- バグ報告や詳細な機能リクエストという形での貢献を歓迎します。
- 外部からのコード貢献は受け付けていません。

*** 資金調達
- ライブラリは強いコピーレフトライセンス（AGPL）の下で無償で利用可能です。
- 一度限りの貢献（$500）により、組織は永続的な商用ライセンスを取得できます。
- 資金調達の閾値（$5,000）を超えた場合、誰もが無償でパーミッシブライセンス（ISC）を取得できます。

* opam リポジトリのパッケージ貢献者は人間が背後にいるべき
:PROPERTIES:
:CUSTOM_ID: 4
:END:
Archive: https://discuss.ocaml.org/t/opam-repository-package-contributors-should-have-a-human-behind-them/18466/1

** Anil Madhavapeddy が発表しました


皆さんへ、

新たに追加した [[https://github.com/ocaml/opam-repository/tree/master/governance/policies#14-package-contributors-accounts-should-have-a-human-behind-them][opam-repository への貢献ガイダンス]] についてお知らせしたいと思います。

#+begin_quote
~14.~ パッケージ貢献者のアカウントには人間が背後にいるべき
~opam-repository~ のメンテナーによるレビュー作業は人間によって行われており、フィードバックに応答できる連絡先が必要です。

*理由:*
- 新しいパッケージの提案はボットアカウントから送信されても構いませんが、PR には人間の連絡先をタグ付けして、opam-repo メンテナーが誰に話しかければよいかわかるようにする必要があります。
- パッケージ公開 PR に関するその後の議論では、メンテナーに過度な負担をかけないよう、大量の LLM 生成レスポンスや自動トリアージログなどの過剰なノイズを避ける必要があります。
- パッケージ公開 PR への機械生成コメントはすべて明示的にそのように識別されなければなりません。
- 人間のレビュアーが質問をしたりガイダンスを提供したりした場合、人間による返答が必要です。
#+end_quote

この動機は二つあります：ボットベースのリリース手順を持つプロジェクトからの投稿が少しずつ増えており、いくつかのケースでは責任者が実際に誰であるかを掘り起こす必要がありました。

そして当然ながら、私たちの哀れな人間の顔に降りかかってくる LLM スパムが増えてきていますが、投稿 PR はこれまでのところ概ね配慮あるものでした。この流れを維持していきましょう！フィードバックはいつでも歓迎です。興味のある方は [[https://github.com/ocaml/opam-repository/pull/30367][PR のディスカッションはこちら]] をご覧いただき、引き続き opam パッケージの投稿をよろしくお願いします :-)
      



* Cohttp 6.3.0 リリース (OSEC-2026-16)
:PROPERTIES:
:CUSTOM_ID: 5
:END:
Archive: https://discuss.ocaml.org/t/cohttp-6-3-0-released-osec-2026-16/18467/1

** Anil Madhavapeddy が発表しました


皆さんへ、

cohttp 6.3.0 が重要なセキュリティ修正（[[https://osv.dev/vulnerability/OSEC-2026-1][OSEC-2026-16]]）とともに opam-repository にリリースされました：

- cohttp: ~Cohttp.Path.resolve_local_file~ は、~..%2f..%2f~ のようなパーセントエンコードされたトラバーサルシーケンスが与えられた場合に docroot を脱出しなくなりました。URI パスは ~.~ および ~..~ セグメントが除去される前に正確に一度だけパーセントデコードされます。
  (#1145 @avsm および Sapphire Livingstone、@mdales @edwintorok @patricoferris によるレビュー)

- cohttp: ~Cohttp.Path.resolve_local_file~ は空のパスセグメントを折り畳み、末尾のスラッシュを削除します。~/dir//sub/~ へのリクエストは ~docroot/dir//sub/~ ではなく ~docroot/dir/sub~ に解決されるようになりました。(#1145 @avsm)

- cohttp: ~Cohttp.Path.normalise~ を追加しました。これはリクエスト URI をルートより上に昇ることができない相対パスに変換します。パスセグメントに対してアクセス制御の判断を行うサーバーは、それらを検査する前に ~Request.uri~ に適用する必要があります。~Request.uri~ は絶対形式またはパーセントエンコードされたターゲットを正規化しないためです。(#1145 @avsm)
  #+begin_src ocaml
  let callback _conn req _body =
    let uri = Cohttp.Request.uri req in
    match String.split_on_char '/' (Cohttp.Path.normalise uri) with
    | "admin" :: _ when not (authorised req) -> Server.respond_not_found ()
    | _ ->
        let fname = Cohttp.Path.resolve_local_file ~docroot ~uri in
        Server.respond_file ~fname ()
  #+end_src
  正規化はデフォルトでは適用されません。既存のコードが現在のセマンティクスに依存している可能性があるためです。現在のセマンティクスはローカルファイル解決と組み合わせなければ安全です。

- cohttp-mirage: 静的ファイルサーバーは、ディレクトリリクエストを含むすべてのリクエストのリクエストパスを、mirage-kv ストアで検索する前に正規化します。キーはパーセントデコードされるようになったため、~/my%20file.txt~ は ~my%20file.txt~ ではなく ~my file.txt~ キーを取得します。(#1145 @avsm、@mdales @edwintorok によるレビュー)

- cohttp-mirage: ~request_fn~ コールバックはリクエスト URI を変更せずに受け取ります。インデックスページにフォールバックするリクエストは以前、そのページに書き換えられた URI を受け取っていました。(#1145 @avsm)

- cohttp: ボディを持てないレスポンス（1xx、204、304）に ~Transfer-Encoding~/~Content-Length~ フレーミングヘッダーを追加しなくなりました。これにより WebSocket ハンドシェイクが修正されます。(@mefyl @avsm、#1141)

- http: レスポンスを手動で構築するユーザー向けに、既存の ~Method.body_allowed~ に対応するレスポンスステータス版として ~Status.body_allowed~ を追加しました。(#1141)

できるだけ早くアップグレードしてください。また、独自の HTTP パス分割のニーズに対応する新しい ~normalise~ 関数もご注目ください。

セキュリティ問題の対応にご協力いただいた皆さん、特に発見・報告・修正のガイダンスをしてくださった Sapphire Livingstone に感謝します：

* opam 2.6.0~alpha1
:PROPERTIES:
:CUSTOM_ID: 6
:END:
Archive: https://discuss.ocaml.org/t/ann-opam-2-6-0-alpha1/18372/3

** このスレッドを引き継いで、Kate が発表しました


皆さんへ、

opam 2.6.0~beta1 のリリースをお知らせできることを嬉しく思います。

このバージョンはベータ版です。安定版リリースに向けて、これまで気づかれなかったバグを発見するためにユーザーのテストをお願いします。

*** 2.6.0~alpha1 からの主な変更点

- :recycling_symbol: ~opam init --reinit~（古い opam バージョンからアップグレード後に通常呼び出されるコマンド）が改善されました。2.1 の opam ルートからアップグレードする際にコマンドの再試行を求めるメッセージが表示されなくなり、opam ルートを変更せずに opam ライブラリを使用するツールがスイッチ情報を読み込めるようにスイッチのメタデータを再生成するようになりました。([[https://github.com/ocaml/opam/issues/7057][#7057]]、[[https://github.com/ocaml/opam/issues/7066][#7066]])

- :houses: ~--safe~ が指定された場合、opam はデバッグレベルを 0 にリセットしていましたが、これはもはや行われません。スクリプトを適宜更新することをご検討ください。([[https://github.com/ocaml/opam/issues/7000][#7000]])

- :shuffle_tracks_button: opam は管理しているリポジトリで git gc/maintenance を無効にするようになりました。これは、git がバックグラウンドでメンテナンスタスクを起動し、ファイルの作成・削除・変更を行うため、それを知らない opam プロセスがそのような git リポジトリを処理する際にレースコンディションで失敗することがあるためです。([[https://github.com/ocaml/opam/issues/7031][#7031]])

:open_book: これらの変更の詳細については [[https://opam.ocaml.org/blog/opam-2-6-0-beta1/][ブログ記事]] をご覧ください。さらに詳しくは [[https://github.com/ocaml/opam/releases/tag/2.6.0-beta1][リリースノート]] または [[https://github.com/ocaml/opam/blob/2.6.0-beta1/CHANGES][changelog]] をご参照ください。


*** 試してみてください！

アップグレード手順は変わっていません：

Unix システムの場合
#+begin_example
bash -c "sh <(curl -fsSL https://opam.ocaml.org/install.sh) --version 2.6.0~beta1"
#+end_example
または Windows システムの PowerShell から
#+begin_example
Invoke-Expression "& { $(Invoke-RestMethod https://opam.ocaml.org/install.ps1) } -Version 2.6.0~beta1"
#+end_example
問題が発生した場合は [[https://github.com/ocaml/opam/issues][バグトラッカー]] にご報告ください。
